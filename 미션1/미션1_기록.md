# 미션 1 기록: 내 영화 티어리스트

## 질문과 결정

- 사용자에게 등급 구성, 이동 방식, 저장 방식을 물었다. 답변: S·A·B·C와 미분류 칸, 클릭·드래그 이동, 브라우저 자동 저장.
- `기획서.md`에 화면, 자료 8편, 완료 기준과 한계를 정리했다.

## 같은 기획으로 만든 두 버전

| 항목 | AI A | AI B |
| --- | --- | --- |
| 서비스 | OpenAI Codex (이 대화, 세부 모델명 확인 필요) | Google Gemini (자동 모드, 세부 모델명 확인 불가) |
| 파일 | `영화티어_Codex.html` | `영화티어_Gemini.html` |
| 구성 | 등급 칸과 카드에 집중한 간결한 화면 | 어두운 화면, 별도의 빠른 이동 버튼과 선택 상태 안내 |
| 기획서 반영 | 기본 8편, 5개 칸, 추가·초기화·자동 저장 | 기본 8편, 5개 칸, 추가·초기화·자동 저장 |

Gemini에는 `기획서.md`와 같은 요구 조건을 프롬프트에 풀어서 전달했다. [Gemini 대화](https://gemini.google.com/app/fafad0432b16ffbc)에서 결과 코드를 다운로드했다. AI A는 이 Codex 대화에서 같은 기획서를 바탕으로 작성했다.

## 브라우저 확인

| 검사 | AI A | AI B |
| --- | --- | --- |
| 처음에 기본 8편이 미분류 | 통과 | 통과 |
| 공백이 있는 `센과 치히로의 행방불명` 선택 후 S로 클릭 이동 | 통과 | 통과 |
| 새로고침 후 S 배치 유지 | 통과 | 통과 |
| `새 영화` 추가 | 통과 | 통과 |
| 기존 `기생충` 제목 중복 차단 | 통과 | 통과 |
| `처음으로` 후 기본 8편 미분류 복귀 | 통과 | 통과 |
| 드래그 이동 | 기생충을 미분류에서 S로 끌어 옮겨 1편·7편 표시 확인 | 자동 조작 두 차례에서 이동되지 않아 원인 미확정 |
| 실제 좁은 화면 | 390px에서 가로 넘침 없음, `Codex_좁은화면.jpg` | 390px에서 가로 넘침 없음, `Gemini_좁은화면.jpg` |

AI A는 이동 대상과 편수가 한 화면에서 보이고 조작 수가 적다. 드래그 이동도 브라우저에서 확인됐다. AI B는 선택 상태와 빠른 이동 버튼이 더 자세하지만 같은 작업을 위한 조작 영역이 여러 곳이다. AI B의 드래그는 자동 조작으로 성공을 확인하지 못했으며 실제 사용자 검증이 필요하다. 확인한 사용성과 간결함을 기준으로 AI A를 첫 버전으로 선택한다.

## 화면 증빙

- `Codex_화면.jpg`: AI A 초기 상태.
- `Gemini_화면.jpg`: AI B 초기 상태.
- `Gemini_대화_공개용.jpg`: Gemini에 기획 조건을 전달하고 HTML 답변을 받은 화면. 개인 대화 목록은 접었다.
- `Codex_좁은화면.jpg`, `Gemini_좁은화면.jpg`: 390px 화면 검증.
- Codex 대화 화면은 이 채팅 자체가 원본이며, 별도 이미지로 저장하지 않았다.
